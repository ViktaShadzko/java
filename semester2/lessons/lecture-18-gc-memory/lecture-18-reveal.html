Структура памяти JVM

JVM Memory
├── Heap (объекты через new)
│   ├── Young Generation
│   │   ├── Eden Space      ← новые объекты
│   │   ├── Survivor S0     ← пережили GC
│   │   └── Survivor S1
│   └── Old Generation      ← долгоживущие
│
├── Stack (per-thread)
│   └── Stack Frame (на каждый вызов)
│       ├── Локальные переменные
│       └── Ссылки на heap объекты
│
├── Metaspace (Java 8+) ← метаданные классов
└── Code Cache          ← JIT код
// Stack хранит:
int x = 10;         // примитив — на стеке
String s = "hello"; // ссылка — на стеке
                    // объект "hello" — на heap!
// Heap хранит:
String obj = new String("world"); // heap
Student st = new Student("Иван"); // heap
// Stack Frame создаётся при вызове метода
// и уничтожается при return
void calculate(int a, int b) {
    int result = a + b; // всё на стеке!
    return result;      // фрейм уничтожается
}

GC и утечки памяти

// GC собирает НЕДОСТИЖИМЫЕ объекты
String a = new String("объект 1"); // heap
String b = new String("объект 2");
a = b;    // "объект 1" недостижим → GC!
b = null; // "объект 2" ещё жив через a!
// ── Утечки памяти в Java ───────────────
// 1. Статическая коллекция без удаления
static List<EventListener> listeners =
    new ArrayList<>();
// добавляем, но никогда не удаляем!
// 2. Бесконечно растущий кэш
static Map<String, HeavyObject> cache =
    new HashMap<>();
// нет ограничения + нет TTL!
// 3. Незакрытые ресурсы
FileReader r = new FileReader("file.txt");
// забыли закрыть! → используй try-with-resources!
// 4. ThreadLocal без remove()
ThreadLocal<HeavyObject> tl = ...;
// В thread pool потоки живут долго!
// Всегда: tl.remove() после использования!
// ── Слабые ссылки ─────────────────────
// WeakReference — удаляется при первом GC
WeakReference<String> weak =
    new WeakReference<>(new String("слабый"));
System.gc();
System.out.println(weak.get()); // null
// WeakHashMap — кэш без утечек!
Map<Object, String> cache =
    new WeakHashMap<>();
Object key = new Object();
cache.put(key, "значение");
key = null; System.gc();
System.out.println(cache.size()); // 0!
// SoftReference — удаляется при нехватке памяти
// ← идеал для кэша изображений!
SoftReference<byte[]> soft =
    new SoftReference<>(loadImage());
byte[] img = soft.get();
if (img == null) img = loadImage(); // промах

📌 Итоги

  • Heap — объекты. Stack — примитивы, ссылки, фреймы.
  • GC собирает недостижимые объекты. Не вызывай System.gc()!
  • Minor GC — быстро (Young). Full GC — медленно (вся куча).
  • Stop-the-World — приложение паузируется при GC.
  • G1, ZGC — современные GC с малыми паузами.
  • Утечки: статические коллекции, ThreadLocal, незакрытые ресурсы.
  • WeakReference — умирает при GC. SoftReference — при нехватке памяти.
